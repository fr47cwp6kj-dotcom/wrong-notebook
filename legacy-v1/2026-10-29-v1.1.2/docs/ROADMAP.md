# 实施路线图

## V1：照片收集

**目标**：iPhone 手动上传错题照片到 Windows 本地目录。

交付：

- Windows 目录结构。
- 本地收件箱管理程序。
- 受限 SMB 共享。
- iPhone 连接与上传指南。
- 环境检查与实机验收。

不做：

- OCR。
- 模型部署。
- 数据库。
- 常驻服务。

## V2：识别与人工校对

**目标**：监听 `待识别`，为新增照片建立记录，输出可校对的题目和答案文本。

关键决策：

- OCR 与多模态模型分别评测，不预先承诺模型名称。
- 以初中、高中真实错题照片建立本地评测集。
- 所有识别结果必须保留 `待核对` 标记。

## V3：错因确认

**目标**：从“错题记录”下沉到“知识单元漏洞诊断”，AI 给出候选卡点和漏洞，学生选择确认。

交互要求：

- 支持表层错因和深层漏洞双层分类。
- 必须定位卡住步骤、未使用条件和触发规则。
- 诊断对象是知识单元组合，不是整道题外壳。
- 支持多选。
- AI 不强制单选。
- AI 不要求学生誊抄题干。
- 原图、题干、原答案和批改痕迹同屏可查。

诊断流程：

```text
识别题目与作答
  -> 拆解解题步骤
  -> 标出第一个明显卡点
  -> 回看未使用条件
  -> 候选知识单元与漏洞类型
  -> 学生确认或标记不确定
  -> 生成最小巩固练习
```

验收指标：

- 每条候选诊断都有题干、作答或批改证据。
- 学生确认时间显著短于手工整理一张完整错题。
- “不确定”能进入待人工处理，不被强行归类。
- 诊断卡能形成“看到 A + B，想到 C”的触发规则。
- 诊断输出符合 [Agent 诊断行为契约](AGENT_PROMPT_CONTRACT.md)。
- 知识单元库从真实错题逐步生长，不一次性生成全学科清单。

## V4：变式题生成

**目标**：围绕确认的知识单元漏洞，生成同考点、同难度量级、可独立求解的变式和拆步练习。

验收必须包含：

- 条件完整性检查。
- 答案与解析生成。
- 人工复核入口。
- 学段边界检查。
- 保留触发条件，适度改变题干外壳和干扰条件。
- 可只生成卡点小题，不强制整题重做。

## V5：复习调度

**目标**：根据知识单元掌握情况和练习结果安排复习。

原则：

- 每日清单只包含待处理、到期和未完成项。
- 间隔参数可配置并基于实际完成情况调整。
- 同一知识单元需在不同题干外壳中验证，防止记住原题。
- 优先复习触发规则和小步推理，再安排完整题综合。
- 临近过期、连续失败和人工标记薄弱的单元优先。
- 不将固定间隔包装为提分保证。

## V6：手机本地网页

**目标**：在 iPhone 上完成上传、确认错因、练习和状态查看。

技术方向：

- 局域网本地 Web/PWA。
- 响应式界面。
- 服务不可用时明确提示，不伪造离线完成状态。
