# 知识漏洞驱动学习闭环实施记录

本文件跟踪 2.0 升级的实际落地情况。公开主线和群晖生产实例应分别验证；代码合入不等于已部署。

## 现有基础

- `KnowledgeUnit` 按用户、学段、学科和规则哈希归档；`GapDiagnosis` 保留题目证据、确认状态和过期标志。
- `UnitPracticeEvent` 记录知识单元小练；`PracticeRecord` 记录举一反三及试卷作答；两套事件尚未形成统一掌握判定。
- 掌握概率、组卷范围和复习日程仍主要以 `ErrorItem` 为中心。知识单元跨题统计只使用原题 ID，不能代替新题情境验证。

## 已实施的证据修正

- 错题掌握确认按不同练习题文本计算跨题情境；隔天重做同一题不增加情境数，缺题目快照的旧记录保守处理。
- 直接查看答案后自报做对、判错后改报做对不计为独立通过。
- 已确认且未过期的诊断可在举一反三页提供逐级提示：未用条件、触发规则、首个卡住步骤。保存最高提示级别；使用提示后作答不计为独立通过。
- 知识单元小练先写自己的答案，再查看参考答案；新事件保留独立作答标记，旧事件默认不计入跨题独立通过。
- 所有 AI 渠道的变式题生成入口拒绝空答案或空解析；这只是基本结构检查，尚不证明数学正确性。
- 已确认且未过期的知识单元诊断参数进入举一反三生成提示词；覆盖四种 AI 提供商。尚未接入试卷生成路径，也未实现题目成对的边界对比和数学求解校验。
- 诊断报告默认只显示最近一条的第一步，逐步展开其余内容；知识单元页显示五阶段验证状态。新诊断提示词可生成边界对比小练，跨题独立通过、边界通过和后续复习分别提供升级证据。

## 后续实施顺序与验收

1. **统一事件与状态**：所有提交、改答、提示、查看解析、追问、复习和新情境验证关联 `KnowledgeUnit` 与题目；记录事实、AI 推断和学生确认的来源。旧数据迁移只补充可证实的信息，未知状态保持未知。导出、导入和用户数据删除同步覆盖新表。测试跨用户隔离、幂等、旧备份、状态回退。
2. **题目生成与审核**：把单元规则、边界、未用条件和首个卡点传入举一反三及组卷；增加规则成立与边界不成立的对比题。生成结果先进入待审核状态；数学可程序验证时检查答案，不能验证时要求人工确认，未通过的题不计掌握。测试错误答案、缺条件、重复和部分失败。
3. **练习与复习接入**：组卷优先未完成跨情境验证的单元；复习按统一状态和间隔表现调度，已掌握后降低同质题频率。题目级统计仍保留以兼容旧视图，但不再作为单元掌握的权威来源。测试同题重复、提示依赖、复习失败回退。
4. **动态诊断**：文字、选项和“不知道”进入限制轮数的追问；多个假设保持不确定，并优先生成区分性问题。学生可纠正结论。测试错误证据引用、低置信度和中途退出。
5. **语义归并与个人预警**：相似单元先召回再按触发条件与边界审核合并；保留来源和撤销路径。个人画像标注样本量；普通练习可显示不泄露答案的预警，考试模拟默认隐藏。测试误合并、撤销、预警有效性。

每一项交付需同步中英文界面、README、Wiki、正式数据库迁移与备份兼容；至少运行相关单元和集成测试。上线群晖前备份生产数据库并在副本验证迁移。完整 2.0 尚未交付。
