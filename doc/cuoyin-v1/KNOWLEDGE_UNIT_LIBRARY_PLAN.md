# 知识单元库建设计划

知识单元库是 V3 诊断和 V4 变式练习的基础。它不应一次性生成“全学科大而全清单”，而应从课程标准、教材和真实错题中逐步生长，并经过人工确认。

## 单元粒度

一个知识单元至少包含：

```text
名称：能被学生理解的短句
定义 / 内容：概念、公式或操作
触发条件：看到什么信号应该想到它
适用边界：什么时候能用，什么时候不能用
 prerequisites：依赖哪些前置单元
常见误用：学生容易混淆的相邻单元
```

粒度过宽的例子：

```text
三角形
函数
圆锥曲线
```

粒度合适的例子：

```text
等腰三角形底边中点 -> 三线合一
二次函数顶点式 -> 对称轴与最值
直线与圆相切 -> 圆心距等于半径
```

## 建库来源

1. 课程标准和教材目录：确定学段边界与术语。
2. 学生真实错题：从卡点中提炼高频单元。
3. 教师批改和人工复盘：校准触发条件与误用边界。
4. 变式练习结果：判断单元是否真的被调用。

优先级：

```text
学生高频卡点 > 学科主干单元 > 低频复杂综合单元
```

## 状态流

```text
candidate
  -> reviewed
  -> approved
  -> active
  -> deprecated
```

- `candidate`：AI 或初稿生成。
- `reviewed`：家长或学生修改过内容。
- `approved`：确认定义、边界和触发条件。
- `active`：可用于诊断和生成练习。
- `deprecated`：拆分、合并或废弃，但保留历史关联。

只有 `approved` 或 `active` 单元能用于自动生成练习。

## 去重与拆分

- 两个单元触发条件不同，即使名称相似也应拆分。
- 两个单元总是同时触发且不可独立练习时，可以合并。
- 一个单元如果超过三个不同前置依赖，通常应拆小。
- 初中和高中分别建库；同名概念以学段边界和适用条件区分。

## 质量验收

| 指标 | 标准 |
| --- | --- |
| 触发条件可观察 | 能指向题干词、图形或数值 |
| 边界明确 | 能举出不可用或易混例子 |
| 可练习 | 能设计 1-5 个小步练习 |
| 学生可读 | 不依赖教师内部术语 |
| 可追溯 | 记录来源和确认状态 |

## 起步做法

V2 收集照片期间，可以先人工维护前 50 个高频数学单元，不追求完整覆盖：

1. 每周从错题中挑 10 个卡点。
2. 合并重复卡点。
3. 为每个卡点写触发规则和最小练习。
4. 月底统计哪些单元反复失败，优先补库。
5. V3 上线时先用这些已确认单元约束 AI，降低幻觉风险。
