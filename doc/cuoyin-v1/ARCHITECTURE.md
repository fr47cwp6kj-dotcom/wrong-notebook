# 总体架构

## 已确认环境

| 项目 | 配置 | 当前用途 |
| --- | --- | --- |
| 手机 | iPhone | V1 拍摄与 SMB 上传 |
| 主机 | Windows 10/11 | V1 存储原始照片 |
| GPU | NVIDIA RTX 3080 Ti，12GB 显存 | V2 以后本地推理候选环境 |
| 学段 | 初中、高中 | 两套知识点与课程边界 |

V1 不依赖 GPU，也不启动 AI 服务。

## V1 数据流

```text
iPhone 拍照 / 相册选择
        |
        v
iPhone 文件 App 连接 SMB
        |
        v
Windows 错因Agent/错题
        |
        +-- 初中/待识别
        +-- 高中/待识别
```

V1 的可靠性来自三个约束：

1. 原始照片始终保留。
2. 手动只选择学段，不要求分科或命名。
3. SMB 共享范围最小化，且仅限家庭局域网。

## 后续数据流

```text
待识别
  -> 目录监听
  -> OCR / 多模态候选识别
  -> 人工校对
  -> 步骤拆解
  -> 知识单元漏洞候选
  -> 学生确认
  -> 卡点小练 / 变式练习
  -> 单元掌握度与复习调度
```

每个阶段必须有失败出口：

- 识别失败进入 `识别失败`。
- 漏洞不确定可以留空或多选。
- 变式题必须有人工复核入口。
- 服务不可用时，原始目录仍可人工浏览。

## 方法论原则

系统反对机械抄题，不把“本子工整”当成学习结果。每道错题的诊断必须尽量回答：

1. 卡在哪一步。
2. 哪个条件信号没有被使用。
3. 哪个知识单元或单元连接缺失。
4. 下次看到什么触发信号应该想起什么。

诊断结果分为两层：表层错因用于观察学习习惯，深层漏洞用于决定补什么和练什么。AI 只能给出带证据的候选，最终由学生确认；无法判断时保留“不确定”，不得为了界面整齐而强行单选。

## 本地优先原则

- 默认所有照片、数据库和服务运行在 Windows 主机。
- 不为了基础收集流程引入公有云依赖。
- V2 选择模型前，需要确认其网络访问、日志、模型下载和隐私行为。
- 不把模型输出当成最终事实；人工确认是流程的一部分。

## 技术决策记录

### V1 选择 SMB

原因：

- 无需开发 iOS App。
- Windows 原生支持。
- 权限模型清晰。

代价：

- 依赖同一局域网和主机在线。
- iPhone 手动操作较多。
- 无断点续传。

### V1 暂不启动监听服务

原因：

- 先验证照片质量、家庭网络和日常操作是否可持续。
- 避免在照片收集未稳定前引入模型部署成本。

### V2 不预设模型

原因：

- 手写、公式、几何图形和 OCR 差异很大。
- 12GB 显存只能作为候选范围，不能保证特定多模态模型可用或达标。
- 需要用真实错题照片做速度、准确率和校对成本评测。

### V3 以知识单元为复习对象

原因：

- 题目外壳无穷，基础知识单元和常见组合有限。
- 只抄题干会消耗大量誊写时间，不能保证定位漏洞。
- 针对“看到 A + B，想到 C”的触发规则，比重复原题更可迁移。

约束：

- 不承诺固定提分幅度或时间。
- 不用 AI 诊断替代学生自己的理解和确认。
- 每条诊断必须能追溯到原图或人工校对文本。
